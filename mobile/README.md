# EXORA Mobile — Android User App (Stage 6.0A/6.0B)

Expo + React Native + TypeScript user/trader app for the EXORA staging CEX,
polished for investor/demo use and prepared for an Android **APK** build via EAS.

**User-only — there is no admin, compliance-officer, RBAC, STR, wallet-risk, or
Travel Rule surface in this app.** The admin panel stays web-only on its own
domain. Android-first; the codebase is kept iOS-compatible for a later Expo/EAS
iOS build (no restructuring needed).

## Tech
- Expo SDK 54, React Native 0.81, React 19, TypeScript (strict)
- Expo Router (file-based navigation, `app/`)
- `expo-secure-store` for token storage (Android Keystore / iOS Keychain)
- `expo-splash-screen` branded splash + adaptive Android icon
- Reusable typed API client, central auth/session context, dark theme,
  loading / skeleton / empty / error states throughout

## Configuration
The API base URL is read from an environment variable — **no secrets in the app**:

```
EXPO_PUBLIC_API_URL=https://dfk68tws8g8oj.cloudfront.net/api/v1
```

Copy `.env.example` → `.env` to override. If unset it defaults to the staging
CloudFront URL above. Only `EXPO_PUBLIC_*` vars are inlined into the bundle. The
`preview`/`production` EAS profiles also set this var (see `eas.json`).

## Setup

```bash
cd mobile
npm install
cp .env.example .env        # optional; defaults to staging
```

Branded assets (icon / adaptive icon / splash / favicon) are generated by a
zero-dependency script and committed under `assets/`. Regenerate any time with:

```bash
node scripts/generate-assets.mjs
```

## Run on an Android phone with Expo Go

1. Install **Expo Go** (Play Store) — make sure it's the **SDK 54** build.
2. Start the dev server:

```bash
npx expo start            # LAN mode (default)
# press "a" to open an Android emulator, or scan the QR with Expo Go
```

### LAN mode (phone + computer on the same Wi-Fi)
```bash
npx expo start --lan
```
Scan the QR in Expo Go. The phone reaches the public API over the internet, so it
works regardless of LAN — only the JS bundle is served over LAN.

### Tunnel mode (different networks / restricted Wi-Fi)
```bash
npx expo start --tunnel
```
Use this when the phone and computer aren't on the same network, or when
corporate/hotel Wi-Fi blocks LAN. (First run may prompt to install `@expo/ngrok`.)

## Build a preview APK (EAS)

```bash
# one-time
npm install -g eas-cli      # or use: npx eas-cli@latest <cmd>
eas login                   # log in to your Expo account
eas build:configure         # links/creates the EAS project id (first time)

# build the installable preview APK
eas build -p android --profile preview
```

`eas.json` → `preview` profile builds an **APK** (`buildType: apk`,
`distribution: internal`). When the build finishes, EAS prints a download URL;
install the `.apk` directly on any Android device (enable "Install unknown apps").
No Play Store release is required for this stage. iOS is intentionally not built
yet (the config is iOS-ready for later).

- App version: `1.0.0` · Android `versionCode: 1` · package `com.exora.mobile`.

## Demo-safe behaviour
- Empty API lists render professional empty states with a clear explanation and a
  relevant call-to-action (e.g. "Make a deposit") — never a blank or broken UI.
- No fake balances or fabricated trades are shown as real data. The only
  non-data UI is the honest **DEMO · STAGING** badge and clearly-labelled empty
  states.
- A failed token refresh signs the user out and returns to Login (no stuck,
  half-authenticated state).

## Known limitations
- "Estimated balance" shows INR available + a per-asset breakdown; cross-asset
  fiat valuation is not computed (no backend valuation endpoint — nothing is
  invented).
- Full enhanced-KYC submission stays on web; the mobile KYC screen is read-only.
- No charts/candles, no live WebSocket feed (fetch on load + pull-to-refresh), no
  push notifications, no clipboard dependency (addresses are long-press-select).
- Withdrawals/deposits use only existing backend behaviour; approvals stay
  admin-side. No real payment/withdrawal behaviour is added.

## Troubleshooting

**"Project is incompatible with this version of Expo Go" / SDK mismatch**
Your Expo Go app must match the project SDK (54). Update Expo Go from the Play
Store, or run `npx expo start` and use the matching build. If you intentionally
need an older client, run `npx expo install expo@<sdk>` — not recommended.

**Android emulator: "adb: command not found" / no device**
Install Android Studio → SDK Platform Tools, then add the platform-tools to PATH:
- Windows: `setx PATH "%PATH%;%LOCALAPPDATA%\Android\Sdk\platform-tools"`
- macOS/Linux: `export PATH=$PATH:~/Library/Android/sdk/platform-tools`
Create an AVD in Android Studio (Device Manager), start it, then press `a` in the
Expo CLI. Verify with `adb devices`.

**QR scan does nothing / phone can't connect**
Use `npx expo start --tunnel`. LAN mode needs the phone and computer on the same
network and no AP/client isolation.

**Metro/cache weirdness after upgrades**
`npx expo start -c` (clears the Metro cache).

**EAS: "project not configured"**
Run `eas build:configure` once (after `eas login`) to create the project id.
